REMAINING VCS: SOURCE REQUIREMENTS AND POSSIBLE SUPPORT

Names below abbreviate the corresponding Pattern... / BucketMapImpl__0__...
declarations. Counts are remaining/total predicate slots, not loop counts.

1. Char.NextMatch — 1/11
   Need: finite character-width cases; immutable map/record frames; conditional
   callback facts linking byte equality, validity and boundaries; exact checked
   addition/subtraction guards.
   Add: bounded definition exposure, local-contract instantiation and consistent
   observation normalization. Current scalar model import should suffice.
   Evidence: a contract-aware reduced query gave an Eldarica Loop model and a
   complete original proof. Its extra bound checks were manually selected.
   First gate: export the actual post-Zap clauses without those extra targets.

2. Str.Next — 1/6
   Need: ghost_str_inv/ghost_tw_dyn structure; shared bytes_eq observations;
   guarded lead-boundary contract; boundary at the end of the string.
   Add: source predicate exposure and automatic derivation of elementary endpoint
   facts from source UTF8 assumptions. Try bounded unfolding/base constructors
   before requiring general UTF8 induction.
   Evidence: saved Forward model is scalar and ignores its boundary-array slot.
   The reduced query explicitly requested the mem=MAX or mem=0 disjunction.
   First gate: obtain an adequate model without inserting that disjunction.

3. Str.NextBack — 1/6
   Need: suffix-memory conditions, guarded needle/tail-boundary contracts,
   boundary at zero, and checked decrement.
   Add: the same source-fact path, retaining branch conditions and source aliases.
   Evidence: saved Backward model is scalar; its memb=MAX or memb=k target was
   manually selected. Full arrays are not prerequisite for that particular model.
   First gate: automatic endpoint/contract handling on original post-Zap clauses.

4. SortMerge — 4/12
   Two substantive invariants: copied interval + frame, and merge-loop bounds,
   sorted output prefix, frame, source membership and next-element comparisons.
   The other two manual witnesses are True.
   Add: function/array reads and updates, cross-array interval properties,
   two-index sortedness and existential source-membership witnesses.
   Source sort_is_perm means one-way range membership plus outside-range equality,
   not multiset permutation. Arrays alone do not supply those quantified facts.
   Gates: copy loop -> sortedness/frame -> membership -> complete original VC.
   Evidence: saved short copy/merge probes timed out or were unknown; their
   correspondence to all original clauses was not proved.

5. MoveElements — 2/3; implementation remains deferred
   One substantive invariant: cleared source prefix, unchanged suffix/length,
   and destination equal to the fold over the processed original prefix.
   The other manual witness is True. Exit requires exact list equalities.
   Add: list/ADT semantics, Int.toNat/default reads and update behavior, and a
   checked generic fold representation with prefix/suffix reasoning.
   The source already supplies new.slots = absorb_bucket(old.slots, source[i]).
   Start with that abstract supplied step; expanding hash insertion/modulo is
   not necessarily required. Raw SMT arrays do not preserve list semantics.
   Gates: index clearing -> fold over supplied step -> combination -> original VC.
   First overlap target is Fix-covered MoveElementsFromList.
   Evidence: numeric models omit the semantic equalities; expanded recursion and
   append-graph experiments failed or timed out. No automatic gain established.

6. TwoWay.Next — 1/10
   Need: equality of shifted byte intervals, periodicity, remembered-prefix
   conditions, sentinel modes, scan callbacks and continuation contracts.
   Add: array reads, generic interval restriction/join/shift support and a sound
   lift of universally quantified observations. Preserve all return contracts.
   First gate: exact interval/scan component, using ScanUp/Down as overlap controls.
   Evidence: numeric core solved; semantic probe was incomplete and unresolved.

7. TwoWay.MaximalSuffix — 1/7
   Source safety includes periodicity and lexicographic dominance:
   for every earlier start, there exists a mismatch, with all earlier bytes equal.
   Add: an adequate encoding of these forall-exists-forall properties, including
   witness/model lifting. Mere array export or opaque Boolean atoms is insufficient.
   The known manual invariant also uses nonlinear divisibility and rotations;
   these are not proved necessary for every possible solver invariant.
   First gate: a faithful small dominance component before major implementation.
   Evidence: Spacer rejected an existential in the tested rule; Eldarica timed out.

8. TwoWay.ReverseMaximalSuffix — 1/9
   Same dominance/periodicity requirements over the affine view m(k-1-i), plus
   the period-bound early exit. This source VC does not require UTF8.
   Add: reuse a successful forward representation with index substitution and
   exact early-exit conditions; do not build an independent reverse encoder.
   First gate: checked reversal mapping after the forward dominance gate.
   Evidence: no validated full-source S/E model.

9. TwoWay.NextBack — 1/10
   Need: reverse interval/memory reasoning, conditional window bounds, and source
   UTF8/boundary preservation, together with checked wrap/overflow behavior.
   Add: search support plus a faithful treatment of inductive UTF8 facts.
   A boundary means valid UTF8 prefix and suffix, not only an integer range.
   First gate: generic boundary preservation before integrating the whole search.
   Evidence: the old semantic query omitted full UTF8 and continuation details.

SHARED EXTENSIONS AND OWNERSHIP

A. Automatic source facts — Facts.lean / Projection.lean
   Discover relevant equations and expose nonrecursive source predicates;
   instantiate local conditional contracts with bounded, typed triggers.
   Retain guards. Derive additional facts with Lean proofs; do not assume desired
   invariants or user-authored per-VC preservation lemmas.

B. Typed observations — Projection.lean
   Normalize aliases, record fields, reads and affine index expressions
   consistently; preserve conditional congruence and stable argument mappings.
   Existing scalar projection remains useful alongside direct theory export.

C. Direct theory round trips — Export.lean / Witness.lean / SMTLib-to-Lean
   Extend sort/operator metadata, export, model parsing, reconstruction and
   lifting together. Start with total Int-indexed maps; add monomorphized list/ADT
   support separately. Preserve Nat/Int and finite-list semantics explicitly.
   Current ValueSort and standalone model import are Bool/Int only.
   lean-smt's generic constructor translator excludes parametric inductives;
   importing it alone does not implement List support.

D. Quantified collection reasoning
   Try proved reusable interval laws or a sound arbitrary-index abstraction.
   One observed index cannot establish two-index sortedness. Finite sampled
   indices cannot replace universal quantification. Existential mismatch/member
   witnesses require their own sound handling and model-lifting story.

E. Recursive/inductive semantics
   Investigate relational graphs or reusable checked fold interpretations.
   Positive constructor clauses alone allow overapproximations; they do not give
   an exact interpretation of source UTF8 or recursive functions. Any bridge
   needed when lifting a model must be justified for its actual use/polarity.

SYSTEMATIC IMPLEMENTATION ORDER

1. Freeze attribution and one S/E baseline.
   Reuse the 24 existing Fix proofs; select the nine remaining cases explicitly.
   Compare separate Spacer and Eldarica runs from identical post-Zap constraints.
   Extend scripts/benchmark_rq1.py and its existing harness rather than add a
   parallel evaluation framework. Record source hashes and preprocessing options.

2. Implement bounded source exposure and contract discovery.
   Exercise existing Str.NextMatch overlap controls, then Char.NextMatch,
   Str.Next and Str.NextBack, in that order. Use only source assumptions,
   generated equations and generic proved rules during synthesis.
   Gate: original heads and a complete residual proof once per claimed gain.

3. Frontload theory feasibility before broad interface work.
   Use exact read/update/copy and fold components from the sources. Retain all
   relevant safety obligations; validate any slicing against the original goal.
   Check returned model shapes and a minimal Lean round trip. Do not generalize
   a failed 5-second hand-reduced probe into an impossibility claim.

4. Implement arrays plus model reconstruction end to end.
   Recheck ScanUp/Down, SortInsert and SortPartition for Fix/S/E overlap.
   Then attack SortMerge incrementally. If quantified membership remains the
   blocker, report it separately from successful array export.

5. Add general interval/observer support where evidence justifies it.
   Check universal lifting and multiple observation indices explicitly.
   Target TwoWay.Next and SortMerge's semantic obligations. Keep existential
   witness support separate from plain universal frame reasoning.

6. Add ADTs and generic recursive-state support as a separate phase.
   Start with ContainsKeyInList/GetInList and MoveElementsFromList overlap.
   Keep outer MoveElements deferred until the smaller fold/list gates succeed.
   Avoid unfolding irrelevant hash/UTF8 internals merely to satisfy an exporter.

7. Investigate the high-risk suffix/UTF8 families.
   MaximalSuffix -> ReverseMaximalSuffix after a faithful dominance probe.
   NextBack follows successful interval support and a valid boundary bridge.
   Stop at an explicit semantic/solver limitation if no general route succeeds.

8. Consolidate and report overlap.
   After each extension rerun affected cases and a small stable regression set.
   At the end run the comparison list once. Report Fix intersection S/E,
   Fix-only, S/E-only and neither, for both VCs and predicate slots.
   Report synthesis time, imported candidates, original heads eliminated,
   adequacy validation and full proof separately. Manual residual proof is
   allowed; automatic closure is a different result. Trivial-witness/preprocess
   gains belong to preprocessing, not the external solver.
